# AI Smart Exam Manager — Comprehensive Improvement Plan

## Goal
Make exam times **tension-free for staff** by adding real-time notifications, AI conflict prediction, internal messaging, smart analytics, and production-ready database support.

---

## Phase 1: Real-Time Notifications via WebSocket
**Why first:** Staff learn about problems instantly instead of discovering them during exams.

### Files to modify/create
| File | Action |
|------|--------|
| `requirements.txt` | Add `flask-socketio==5.3.6`, `eventlet==0.35.1`, `psycopg2-binary==2.9.9` |
| `models.py` | Add `Notification` model (id, user_id FK, title, message, category, severity, is_read, link, created_at) |
| `realtime.py` | **NEW** — Flask-SocketIO init, room-based event routing (user rooms, role rooms, all_users room), `emit_notification()`, `emit_broadcast()`, `emit_role_notification()` |
| `notification_service.py` | **NEW** — `create_notification()` (persist + push), `broadcast_notification()` (all active users), `get_user_notifications()` |
| `app.py` | Initialize SocketIO, import realtime module, wire notifications into existing events: exam generation, emergency handling, restock approve/reject, daily inventory alerts |

### Notification trigger points in app.py
- `POST /api/exams/generate` → broadcast "Schedule generated" to all
- `POST /api/emergency/room` → broadcast critical "Room emergency" 
- `POST /api/emergency/invigilator` → broadcast critical "Invigilator unavailable"
- `POST /api/restocks/<id>/approve` → notify requesting user
- `POST /api/restocks/<id>/reject` → notify requesting user
- `POST /api/restocks` (new request) → notify admins

### Frontend (all 3 portals)
- Add notification bell icon with unread badge in header
- Notification dropdown panel showing recent notifications
- SocketIO client connection on page load
- Visual + audio alert for critical notifications

## Phase 2: AI Conflict Prediction Engine
**Why second:** Prevents exam-day disasters by detecting issues before they happen.

### Files to modify
| File | Action |
|------|--------|
| `models.py` | Add `ConflictPrediction` model (id, conflict_type, severity, title, description, affected_resources JSON, suggested_fix, status, detected_at, resolved_at) |
| `ai_engine.py` | Add `ConflictPredictor` class with static methods for 5 detection types |
| `app.py` | Add 3 new routes: `POST /api/conflicts/detect`, `GET /api/conflicts`, `POST /api/conflicts/<id>/resolve` |

### Conflict types to detect
1. **Room overcrowding** — exam student count > 90% room capacity
2. **Invigilator burnout** — fatigue_score > 80 or 3+ consecutive heavy days
3. **Schedule collisions** — same branch exams scheduled in overlapping time slots
4. **Inventory critical** — items with days_until_low < 3
5. **Student double-booking** — same student assigned to exams at same time

### Frontend
- New "Conflict Monitor" section in admin dashboard
- Conflict cards with severity badges (critical/warning/info)
- One-click resolve button per conflict
- Auto-refresh via SocketIO when new conflicts detected

## Phase 5: PostgreSQL Support + Config
**Why fifth:** Enables production deployment while keeping SQLite for demo.

### Files to modify
| File | Action |
|------|--------|
| `config.py` | Add PostgreSQL URI to ProductionConfig (env var `DATABASE_URL`), keep SQLite as DevelopmentConfig default |
| `app.py` | Add `create_app()` factory function for proper SocketIO integration |
| `.env.example` | Add `DATABASE_URL`, `REDIS_URL` (for SocketIO scaling) |

### Dual-database strategy
- **Development**: SQLite (zero-config, portable demo)
- **Production**: PostgreSQL via `DATABASE_URL` env var
- Models already use `db.Text` and proper indexes — no schema changes needed
